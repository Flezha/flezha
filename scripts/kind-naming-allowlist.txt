# Preserved occurrences of "bounded" / "unbounded".
#
# The two operative kinds are `stream` and `workflow`. The words "bounded" and
# "unbounded" survive in this repository in two other senses, and this file
# tells `scripts/check-kind-naming.sh` how to recognise them so they are not
# read as a kind-sense regression.
#
#   capacity — a mailbox with a capacity limit (`BoundedMailboxSource`,
#              `:flezha_bounded_mailbox`, "backpressure and bounded mailboxes")
#   english  — ordinary usage: "bounded by the deadline", "a bounded (1024)
#              FIFO", "bounded cardinality", "unbounded growth"
#
# THREE mechanisms cover those two senses. Reach for them in this order.
#
# 1. The gate's own KIND-SENSE PATTERNS, in `check-kind-naming.sh`, decide what
#    this file may not excuse. They match `bounded`/`unbounded` bound to a noun
#    that can only name the operative construct — `operative`, `kind`, `class`,
#    `factory`, and a `kind`/`operative` predicated to BE the retired name. No
#    entry here can mask them, so a broad rule below is safe: it cannot hide the
#    error the gate exists to catch. Widening those patterns is how the gate
#    gets stronger; adding entries here is how it gets quieter.
#
# 2. SHAPE RULES here, matching how the legitimate senses are WRITTEN rather
#    than which nouns they use. The plain-English sense takes an open-ended set
#    of nouns — every new limit anyone describes is a new noun — so enumerating
#    them makes the gate go red on correct prose about once a week. Prefer a
#    rule that describes the shape ("the word applied to a following word", "the
#    word quoted as a token") over one that pins a phrase.
#
# 3. `kind-naming-record:begin` / `kind-naming-record:end` comments, for a block
#    that deliberately spells the words out — a changelog entry, a public-API
#    rename table, the glossary paragraph that keeps `bounded`/`unbounded` as
#    adjectives for the RUN, a resolved defect entry quoting the gate's output.
#    Greppable, scoped to the block, and it does not pin the prose's exact
#    wording the way a regex here would.
#
# Format: <path-prefix>:<regex>   (first colon separates; `*` matches any path)
# The checker DELETES every match of <regex> from a line and then looks for a
# residual identifier CONTAINING `bounded` — so `BoundedOperative` and
# `spawn_bounded` are caught, not only the bare word, and a line carrying two
# senses is excused only for the phrase named here. Because erasure is
# destructive and runs in file order, every rule that masks the bare word
# carries `(?<![A-Za-z0-9_])` or a `\b`: without it a rule written for prose
# cuts an identifier in half and the residue no longer says `bounded`.
#
# NOT a target of the rename and NOT listed here: the binding word family —
# `bound`, `unbound`, `bind`, `rebind`, `misbound`, `inbound`, `outbound`,
# `bound_runner`, `bound_ns`, `bound_operatives`, `plugin_bound`,
# `require_bound_principal`, `principal_not_bound`. Those mean *attached to a
# runner or namespace*, `unbound` ("not placed") is unrelated to `unbounded`,
# and none of them contains `bounded` — so the family is untouched by
# construction rather than by an entry here.

# --- third-party API (crossbeam channel constructors) -------------------
*:channel::\{?(un)?bounded
*:= (un)?bounded(::<[^>]*>)?\(

# --- capacity sense -----------------------------------------------------
# The mailbox family, in every case convention it is written in.
*:bounded_mailbox
*:[Bb]ounded[Mm]ailbox
*:BOUNDED_MAILBOX

# --- plain English and capacity: the ATTRIBUTIVE shape ------------------
# The word applied to a following word — "bounded by", "bounded wait",
# "unbounded growth", "bounded (1024) FIFO", "bounded `Task.async_stream`".
# One rule instead of an enumeration of the nouns a limit can have, because
# that enumeration is open-ended and chasing it is what kept this gate red.
# A kind-sense use of this shape ("a bounded operative", "the bounded kind")
# is caught by the gate's kind-sense patterns, which this cannot mask.
#
# Three separators and three cases, because the shape is written in all of
# them: a space in prose, a hyphen in a compound, an underscore in an
# identifier (`bounded_id` — an id kept within a limit, the same attributive
# sense `bounded_mailbox` carries). ALL CAPS is this repository's emphasis in
# prose, so the shape appears as `BOUNDED per-turn state` too. The underscore
# is safe for the same reason the whole rule is: the kind-sense patterns match
# the word bound to `operative`/`kind`/`class`/`factory` through separators
# that include `_`, so `bounded_operative` stays caught however this reads.
# A closing emphasis marker sits between the word and its noun in prose that
# stresses it (`a *bounded* run`). Emphasis is orthogonal to the sense, and a
# kind-sense use written the same way stays caught: the kind-sense patterns
# already step over `*` on their way to `operative`/`kind`/`class`/`factory`.
*:(?<![A-Za-z0-9_])(?:[Uu]n|UN)?(?:[Bb]ounded|BOUNDED)[*_]?[ \-_][A-Za-z0-9`"(]

# The word MENTIONED as a token rather than used — quoted or in a code span,
# as prose about the naming itself does. A kind atom (`:bounded`) keeps its
# colon and an identifier (`bounded_put`) keeps its tail, so neither matches.
*:(?:[`"](?:[Uu]n)?[Bb]ounded\b|\b(?:[Uu]n)?[Bb]ounded[`"])

# Line-wrapped prose whose noun landed on the next line. Restricted to a
# preceding determiner or preposition: after a verb ("the operative it
# declares is bounded") the line reads as a claim about the subject, and that
# shape stays caught.
*:\b(?:a|an|the|its|one|same|of|to|from|with|over|and|per) (?:un)?bounded$

# The adverb. It qualifies a verb, so it can never be naming a kind.
*:(?<![A-Za-z0-9_])(?:[Uu]n)?[Bb]oundedly

# --- plain English: the PREDICATIVE shape -------------------------------
# "X is/stays bounded", anchored to the noun X. Deliberately NOT generalised
# to any subject: "<something> is bounded" is exactly how a kind-sense claim
# would read, so each legitimate subject is named.
*:(stay|stays|SHALL be) bounded
*:(memory|[Cc]ardinality|back-pressure|cost|wait|buffer|pull|park|handshake|depth) is bounded
*:mailbox (is |)bounded
*:(grow(s|ing)?|count is) unbounded
*:channel is unbounded
*:drain is bounded
*:drain had to be BOUNDED
docs/sdk/poll_core.md:holdback is \*\*bounded\*\*
docs/plugins/http_poll.md:would be unbounded$

# --- plain English: the bare adjective, standing alone -------------------
# Followed by a comma, wrapped in parentheses, or set off by a dash.
*:(?<![A-Za-z0-9_])[Bb]ounded,
*:\((?:un)?bounded\)

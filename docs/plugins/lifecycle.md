# Plugin provider lifecycle

For authors of plugin providers — the modules an operative host
(`Flezha.Operative.Overwatch`) attaches through `Flezha.Plugin.Extension.Table`. It covers
the two phases and the split between `init_provider/1` and `activate/1`, the optional
callbacks, the identity the host injects, phase and health introspection, the restart
policy, the shared helpers for queue-holding workers, and teardown. Packaging is in
[installation.md](installation.md).

## Two phases

| Phase | Meaning |
| --- | --- |
| `:prepared` | `init_provider/1` has run: config validated, local processes started. The provider is callable but has not been told to acquire upstream resources. |
| `:running` | `activate/1` has run (or the provider exports none): upstream connections open, handshakes issued, input may flow. |

The host moves every `:prepared` plugin to `:running` with
`Flezha.Plugin.Extension.Table.bulk_activate/2`, and only after `start_operative_sdk/2`
has returned `{:ok, _}` — the SDK-side operative is bound and can take input. A provider
that opens its upstream in `init_provider/1` instead runs that connection through every
failed or stalled bind, queueing frames into an operative that cannot drain them.

## `init_provider/1`

Optional. Receives the opts map with the host identity merged in and returns `{:ok, opts}`,
`{:ok, opts, pid | nil}` or `{:error, reason}`; any other shape is
`{:error, {:invalid_init_provider_return, other}}`. A returned pid becomes the tracked
`:owned_pid`. Without the export, the stored opts are used as-is.

Put here: config validation and coercion, `start_link` of a local process (a worker, a
supervisor, a collector), struct construction — anything fast, deterministic and local;
the host's supervisor is waiting on the call. Not here: TLS handshakes, subscribe-style
handshakes that solicit upstream traffic, long blocking calls, anything that assumes the
SDK side is bound — it is not yet.

## `activate/1`

Optional, `activate(opts :: map()) :: :ok | {:ok, pid()} | {:error, term()}`. Implement it
when the provider opens a TCP/TLS connection, issues a protocol handshake (websocket
subscribe, Kafka version negotiation, NATS subscription) or acquires anything whose health
depends on the operative being bound. `opts` is the stored map with `activation_env`
merged last.

- `{:ok, pid}` — tracked as `:owned_pid` and monitored; `:ok` or any other `{:ok, ...}` —
  the plugin is `:running`.
- `{:error, _}`, an invalid return or a raise — logged at `:error`; the plugin stays
  `:prepared`.

A provider without `activate/1` goes straight to `:running`.

### Restarts

An owned pid exiting `:normal` unsubscribes the plugin. On any other exit the host re-runs
`init_provider/1` after a backoff that starts at 4 s (`:plugin_retry_base_delay_ms`),
doubles per attempt and is capped at 60 s; the counter resets only once an owned pid has
stayed up 60 s, so a provider that fails fast keeps backing off. A provider with
`activate/1` drops back to `:prepared` and is re-activated if it was `:running`; one
without returns to `:running` directly. `activate/1` therefore runs on every restart and
every bind.

## Subscription sub-options

`opts` is declared per dispatch kind in `Flezha.Plugin.Extension.Table`, which is
the sole authority on which sub-options exist and what type each carries:

| Kind | Sub-options |
| --- | --- |
| `:fold` | `position` (integer), `timeout_ms` (integer), `on_error` (`"fail"` or `"empty"`) |
| `:transform` | `position` (integer) |
| `:request` | `key` (string) |
| `:timer` | `interval_ms` (integer) |
| `:fanout` | — |

`Extension.Table.canonicalise/2` types the whole declaration before it is
validated, so the same subscription can be written from Elixir, from
`--extension=NAME --NAME.key=value`, from a `--plugins` spec or from an
installed package manifest and mean the same thing: an extension name may be
text or an atom and `opts` a map or a keyword list, and every value is coerced
to its declared type. What the table stores — and what `flz plugin enable`
persists as declared intent — is the canonical `{atom, keyword}` form.

Nothing an operator types is interned. A name that resolves to no extension is
`{:error, {:unknown_extension, name}}`, a sub-option the kind does not declare
is `{:error, {:unknown_subscription_opt, kind, name}}` (`position` on an
unordered kind keeps its own `{:error, :position_not_applicable}`), and a value
that cannot be coerced is `{:error, {:invalid_subscription_opts, {name,
value}}}`. All three are refused at declaration time, before any durable record
of the plugin exists.

## Callbacks

A subscription `{extension, opts}` requires the export `<extension>/2`
(`{:error, {:missing_callback, name}}` otherwise). The rest:

| Callback | Purpose |
| --- | --- |
| `plugin_type/0` | `:io_binding`; required with `use Flezha.Plugin.ProviderBehaviour` |
| `build/1`, `help/0`, `provider_info/0` | generated by `use ProviderBehaviour` for the `flz plugin enable ... --Xkey=value` path; the last two are overridable |
| `health/1` | verdict for a `:running` instance: `:healthy` or `{:unhealthy, reason}`; `opts` carries `:owned_pid` |
| `inspect_state/1` | operator-facing map rendered by `flz operative info`, or `nil` |
| `terminate_provider/1` | release processes beyond the one `:owned_pid`; idempotent; runs on disable and teardown |

Declaring `@known_opts [...]` (optionally `@internal_opts`) makes the option set strict:
`build/1` refuses unknown `--X` keys and the generated `validate_opts/1` — call it first in
`init_provider/1` — refuses unknown keys on the `--plugins` spec path, which never builds
the struct. The host-injected keys (`ProviderBehaviour.host_opts/0`) are always allowed.

## Host identity

`init_provider/1` receives, merged last so stored config cannot spoof them:
`:source_namespace` and `:source_operative_id` (the operative the plugin is enabled on) and
`:source_plugin_id` (for a provider that persists its own committed state). `activate/1`
receives the bind-time operative facts the same way (`activation_env`, currently
`:effectively_once`). `OperativeForward` uses the identity to refuse a self-target or a
cross-namespace target at enable time.

## Introspection

```elixir
Flezha.Plugin.Extension.Table.phase(table, plugin_id)   #=> :prepared | :running | :unknown
Flezha.Plugin.Extension.Table.health(table)             #=> %{plugin_id => :healthy | {:unhealthy, reason}}
```

Only `:running` plugins are probed; a `:prepared` one reports `:healthy`. Without
`health/1` a plugin is healthy while its owned pid is alive (or absent). A `health/1` that
raises or exceeds `ProviderBehaviour.probe_budget_ms/0` (500 ms) reads as `:healthy` —
convergence never escalates on an uncertain probe. An unhealthy verdict is what convergence
restarts the plugin on (`FLEZHA_CONVERGENCE_PLUGIN_STRIKE_THRESHOLD`, default 2).

## In-tree providers

| Provider | `init_provider/1` | `activate/1` |
| --- | --- | --- |
| `Websocket` | normalises opts, validates the URI and any [subscription source](websocket_subscription.md) | opens the connection and runs the subscribe handshake |
| `HttpPoll` | validates URL, channel, headers and tunables; no request | starts the poller; the first request is scheduled, not executed |
| `Kafka.Producer` | starts the per-`(plugin, topic, partition)` `ProducerWorker` | none — the broker connection is lazy |
| `Postgres` | starts the `SinkWorker` | none |
| `OperativeForward` | refuses a self / cross-namespace target, resolves the target's members, starts one `ForwardWorker` per member (re-resolving on every re-prepare); exports `terminate_provider/1` | none — driven by `:on_output` |
| `Filter` | compiles the regex | none |
| `MonitoredIOForward` | starts a local GenServer | none |
| `BeamMsgForward`, `MessageForward`, `StdOut`, `Metrics` | none — stored opts used as-is | none |

## Shared helpers for queue-holding workers

Providers that buffer records towards a slow destination (`Postgres.SinkWorker`,
`OperativeForward.ForwardWorker`) share one supervision core and the policy helpers in
`Flezha.Plugin.ProviderBehaviour`:

| Helper | Purpose |
| --- | --- |
| `Flezha.Plugin.Provider.WorkerSup` | Registry + DynamicSupervisor per provider family: `ensure_worker/4` (reuse while `reusable?` holds, else reap and restart), `stop_worker/2` |
| `retry_backoff_ms/3` | `base × 2^(attempt-1)`, capped; `attempt` counts from 1 |
| `saturated?/1`, `park_or_reply/2`, `release_waiters/1` | the "delay, never loss" overflow policy over `:buffer_len`, `:queue_max`, `:waiters` in the worker state |
| `worker_health/3` | the `health/1` preamble: absent / dead verdicts, else the provider's verdict computed off the caller under the probe budget |
| `ask/3` | a bare `{tag, from, ref}` probe for workers a `GenServer.call` must not queue behind |

The Kafka producer bounds its queue too but offers drop modes, so it keeps its own overflow
handling. Two rules:

- **Never deliver from the worker's own `handle_call`.** A worker blocked on a downstream
  call stops servicing enqueues and back-pressures into the source Overwatch; when the
  destination is another forwarding operative that is a four-way deadlock. `ForwardWorker`
  spawns a monitored process per in-flight item for this reason.
- **Choose `restart:` deliberately.** A disable stops the owned pid with `:shutdown`. A
  `:permanent` child is restarted by its DynamicSupervisor and outlives the disable; a
  `:transient` one stays down. `ForwardWorker` and `ProducerWorker` are `:transient`
  because disabled must mean stopped.

## Enabling: claim, then subscribe

`Flezha.Service.PluginManager` canonicalises and type-checks the subscriptions against the
host catalog first, so an ill-typed, undeclared or unknown one is refused before any
durable record exists and the convergence loop is never handed intent that can never be
satisfied. It then serialises only the id claim; the caller writes the cspec row and
subscribes on the host, and a failed enable releases the claim. Ids whose enable is
in flight are reported by `PluginManager.pending_ids/0` and are not healed by convergence.

Re-enabling an id already registered for the **same** operative in the same namespace is a
no-op that exits 0: no cspec write, no re-subscribe, the live worker keeps running. Options
are not compared — changing opts means disable + enable. The same id against a different
target is an error naming the holder. Against a partition group, already-enabled members
count as success and the summary reports enabled vs already-enabled counts; a failing
member is a loud error. A cold-start script can therefore re-run its `flz plugin enable`
lines unconditionally.

## Teardown

`Flezha.Plugin.Extension.Table.teardown_all/1` and a disable handle both phases uniformly:
`terminate_provider/1` runs if exported, the owned pid is stopped with `:shutdown`, timers
cancelled, monitors released, the `PluginManager` registration dropped. The table tracks
exactly one `:owned_pid`; a provider owning more must implement `terminate_provider/1`
(idempotent — disable followed by stop calls it twice).
